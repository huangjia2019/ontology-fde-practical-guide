这份记录不考你记住多少术语。每做一次练习，留下自己的判断、运行结果和没有想明白的问题。以后回看，你会知道哪些认识来自实践，哪些还只是猜测。

## 只改一个条件：业务不变，换一个执行者

先预测：500 元的申请，所有业务条件都满足，但执行者没有登记，结果会怎样？

```bash
# 已登记的退款助手
python3 run.py run YF-R-0500 --mode write

# 同一笔业务，换成一个未登记的执行者
python3 run.py run YF-R-0500 --mode write --actor agent.marketing.unknown
```

第二次应被身份检查拦下，命中 `G-ACTOR`，不批准、不生成付款指令。两条命令各自使用初始样例，区别只有执行者。

把这次结果和 500 / 500.01 元的比较放在一起：

- 金额改变，业务动作的范围可能改变。
- 金额不变，执行者改变，动作也可能被拒绝。

接下来请你解释：为什么“这件事符合规则”和“这个人或 Agent 可以执行”要分别检查？如果公司的所有助手共用一个账号，事后还能分清谁做了什么吗？

```text

下次准备验证什么：

```

决策编号按引擎实例内的顺序生成，不保证跨进程唯一。多轮 CLI 输出请用不同文件名，结合 `trace_id` 区分记录。别把重新启动后的同号记录误认作同一次执行。

## 学到哪一步，可以往企业现场走

试着选一笔你熟悉、能够获准讨论的业务，不急着接系统。写清对象、来源、允许的动作、停止条件和接手人，请一位业务同事指出遗漏。

如果你们对同一个词理解不同，就把差异记下来。遇到资料不足，也不必硬画出一张完整的大图。先弄明白这笔业务，下次再扩大范围。模型在这些核实和修正中逐渐长出来。
