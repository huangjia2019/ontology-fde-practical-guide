# 第 1 站：拿六个问题检查方案

假如方案写着“接入客服知识库和退款 API，建设企业客服 Agent”，你还需要问什么？沿着一笔退款往下问，每个回答都应该有材料可以查。

| 问题 | 需要看到的材料 | 云帆项目对应位置 |
|---|---|---|
| 谁在执行？ | 独立身份、业务负责人、技术负责人 | [身份配置](../../config/identity/refund_agent.yaml) |
| 处理哪个对象？ | 退款唯一编号、相关订单、当前状态 | [对象与状态](../../config/ontology/) |
| 可以改变什么？ | 查询、建议与写入的区别，动作前提和效果 | [动作契约](../../config/actions/) |
| 凭什么判断？ | 正式规则、经验、个案证据各自的来源与用途 | [规则资产](06-rule-assets.md) |
| 谁授予权限？ | 授权主体、动作范围、条件、期限和环境 | [权限配置](../../config/policies/permissions.yaml) |
| 出错后怎么查、谁接手？ | 决策记录、失败状态、人工处理材料 | [评估与复盘](09-evaluation-audit-and-incident-replay.md) |

## 看看程序里是否找得到

```bash
python3 run.py summary
python3 run.py identity
```

`summary` 提供来源和对象图等概况，`identity` 展开身份及其能力范围。随后选一笔申请，用 `inspect` 查看它的事实。概况数字不能回答某一笔退款为什么该批准，这需要继续查相应对象、规则和权限。

把缺项记录下来，并指定核实的人：业务负责人确定要处理什么，数据负责人确认事实，安全人员确认授权，运维和财务确认失败处理。若只能找到聊天记录里的口头承诺，先整理成可审查的材料，再申请写权限。
